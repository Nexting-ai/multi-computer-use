# One page, many cursors: the shared canvas (2026-11-06)

Exploratory runs, not preregistered: one run per arm per round, on one Mac (local page and browser; only model calls leave the machine). Model: `gpt-6-astra` (medium).

## Task

Reproduce a 64 × 40 pixel picture (a skyline at sunset with the word NEXTING) on one shared page (`lab/canvas`).
- Every cursor is its own browser session on the same document. All cursors and all paint appear live for everyone.
- The tools are Pixel and Rectangle, plus 12 colour swatches; everything is done by clicking.
- The target is given as a text grid. A cursor runs at most 40 clicks per decision.
- Every change and cursor move is logged with a timestamp (`log.jsonl`), so each run replays exactly.

| Arm | Setup |
|---|---|
| one | 1 agent, 1 cursor: conventional Computer Use |
| multi | 1 agent, 12 cursors: one decision gives every cursor its own clicks, run at the same time |
| swarm | 12 agents with 1 cursor each, each given a twelfth of the picture |

## What it shows

- **More hands help only when doing is slower than deciding.** A decision took the model 20–30 s. In an application that applies a click instantly (rounds 1–2), 40 clicks took about 4 s. So 12 cursors did not shorten the run, and in round 2 multi was slowest: one decision for 12 cursors means writing 12 times as many actions.
- **Real applications respond in time.** With 0.8 s per drawing click (round 3), one cursor needed 334 s. One agent with 12 cursors finished in 106 s, 3.2× faster, with a third of the tokens.
- **Twelve agents start fastest but cost 8×.** They think in parallel, so they reach 90% sooner (56 s against 83 s), but they used 1.64M tokens against 0.20M, and finished later (133 s) because the last regions straggled.
- **The harness's case: one decision, many slow hands.** It applies wherever each action has to wait for the application (page loads, saves, renders, exports) and one decision can keep many hands busy.
