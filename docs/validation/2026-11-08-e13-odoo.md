# E13 results: one agent over four real Odoo desktops (2026-11-08)

Two paired, fresh-seed blocks compare conventional single-desktop visual Computer Use (P-V) with one director over four real Odoo 17 desktops (F). Every company requires a confirmed order, completed delivery, posted invoice, and reconciled full payment through the GUI. The model is `gpt-6-astra` (medium).

Total tokens include cached input and are not a direct dollar-cost measurement. The sessions listed for F are one director in block 1 and one director plus one continuation in block 2; there are no per-desktop helper agents. P-V uses independent single-desktop sessions in strict sequence.

### Block 1: a same-completion comparison

Both arms independently verify 4/4 with zero wrong records. The fleet is **3.4409× faster** and uses **58.4% fewer tokens** and **60.3% fewer tool calls**. W01 needed a retry in the baseline after a product price did not populate; it eventually completed correctly. The fleet created the missing customer as a company, reused the existing W03 order without duplication, and handled W04's layout and notice.

The main film uses this block because block 1 was designated before results were known. It is not selected as the best run.

### Block 2: completion reliability and a budget-censored baseline

The fleet again verifies 4/4 with zero wrong records, using one continuation. The baseline verifies 3/4 and stops at the 6M token budget. Its W04 has a correct confirmed order and completed delivery, but its invoice is still draft and there is no payment; this is incomplete work, not a wrong record.

The observed time ratio is 1.8455, but **it is not a same-completion speed estimate** because the baseline stopped unfinished. The fleet nevertheless used 3.45M tokens against the baseline's 6.03M and completed all four workflows.

## Aggregate, with the censoring preserved

- Fleet: **8/8 companies**, zero wrong records.
- Baseline: **7/8 companies**, zero wrong records, one budget-stopped incomplete company.
- Median observed elapsed time: baseline **1,024.971 s (17:04.971)**, fleet **411.716 s (6:51.716)**. Their ratio is 2.4895, but it is descriptive only because block 2's baseline is budget-censored.
- Median total tokens: baseline **6,030,604**, fleet **2,980,740**. The ratio is 2.0232, or about **50.6% fewer tokens** on this two-block median.

These are two pairs on real Odoo 17 in English, not proof of a universal multiplier, performance on other Odoo versions or languages, stock shortages, or arbitrary websites.

## Independent verification and film

The final analysis reruns the scorer in a separate process and checks that every score matches the runner's preserved result. For every successful company it also asserts one order, one delivery, one invoice, one payment, a done delivery, a posted and paid invoice, and a posted payment reconciled to that invoice. The source hashes in every frozen run plan must match the preregistration.

All four desktop recordings cover every measured run. Block 1's baseline has 2,293 frames per surface; block 1's fleet has 673; block 2's fleet has 988; block 2's baseline has 1,816. A recorder shutdown race lost only block 1 fleet's metadata file, not any frame. It was reproduced, fixed before block 2, and the metadata was explicitly recovered from the preserved frames. Browser-close and initial target-discovery messages are retained in the recorder metadata.

The film replays real screenshots and timestamped `input_ack` events on one shared wall clock. It does not synthesize actions or alter the result. One generic Odoo Onboarding title is blurred for privacy without changing operations, timing, or evidence. The delivered MP4 is 1,920 × 1,080, 60.2 seconds, SHA-256 `6ee108592bdf94f0488834035451994a6f101cd1f3b83486747bc0a373253fbe`, and passes the final privacy scan with **120 sampled frames and zero hits**.

All companies and business records are synthetic. The `admin/admin` Odoo login and `odoo/odoo` database credentials are deliberate defaults inside disposable isolated test environments, not real user accounts or secrets. They must not be reused in a deployed environment.

The repository's standard verification also passed: **16 test files and 105 tests**, plus seven video-timeline tests.
