# Bounded visual worksets and host-owned completion

These changes followed a failed 100-desktop study. The previous campaign remains immutable. The implementation is a reusable SDK runtime between capture and input, not a fixture-specific click script.

## Cost model and falsifiers

Total provider tokens are the sum of each inference pass's input and output. Input includes the retained history; cached input still belongs in total tokens. Shrinking a new image does not remove past images, schema text, or tool results. With repeated passes over accumulating evidence, total exposure can grow quadratically in the number of passes; bounded independent worksets cap that history at the price of repeated session setup and instructions. Provider accounting, rather than image area estimates, decides the outcome. We cannot identify image-token costs precisely from aggregate usage alone.

Wall time comprises observation transport, decision passes, guarded input, verification, and recovery. A batch barrier waits for its slowest member. Ready results must be consumable before an unrelated pending target finishes. Reconnect retrieves an immutable receipt; it does not authorize replay of an uncertain input.

## Contract

- Persist a task manifest and per-target progress outside model context. A model turn ending never marks a target complete. Each target requires all declared steps with fresh visual verification; delivery alone is insufficient. Model visual verification remains a claim, separately checked by the benchmark's independent business grader.
- Keep at most eight targets in one visual session. Each workset gets a fresh Astra session with only its current progress and required fresh pixels, no prior screenshots or prose transcript. Both experiment arms receive identical orchestration, verification, concurrency, budgets and recovery. All sub-session usage, failed attempts and setup time count.
- A durable dispatch intent precedes input. After a crash, an unresolved intent becomes unknown and cannot be dispatched again. Explicit no-input rejection permits fresh observation; delivered inputs await verification. Wrong results block that target rather than silently becoming done.
- Capture and input settle independently per target. A bounded collection window returns available results and identifies pending/error targets. Successful pixels survive another target's failure. Read retries are bounded and only failed targets are retried; healthy targets do not wait through their retry budget.
- Exact field expectations are bound before dispatch; post-input observations are checked against those expectations. This does not magically correct a model's initial F/E misreading. Independent grading remains unavailable to the model and scheduler.
- Stable Z is a surface address, not a 3D model embedding. All coordinate bindings remain immutable; explicit scope prevents a workset from operating other targets. Role selection continues to come from model-observed original pixels.
- Use a persistent multiplexed SSH relay over the same durable spool for the new comparison. Its loss cannot kill the detached executor. Both arms use it, so transport improvement is not attributed to role composition.

## Validation and experiment

Test early model termination, a target that never resolves while others advance, partial capture failure, crash after dispatch, duplicate request identity, stale verification, false completion, scope violations, bounded retries and complete accounting across sessions. Verify real browser integration before cloud spend. Then a small real-Astra manipulation check must demonstrate completion across multiple worksets before four paired trials of 100 independent server desktops.

Freeze new source/image/tools/prompts/order/budgets before formal trials. Use same Astra medium, independent sessions and environments, balanced randomized order, four new paired seeds, 300 task items per arm per pair. No failed post-input trial is replaced. Only pairs with equal full submission coverage qualify for time/token comparison; success and wrong/duplicate/misrouting gates must also pass. Failure to finish is itself a failed acceptance, not permission to discard the sample. Do not force success by reading grader answers or retrying an already committed save. Report provider/transport faults separately and retain them in end-to-end costs.

Graphical replay must expose workset boundaries, remaining/verified/unknown states and real image-to-source actions; it is read-only.

Implementation details frozen for the new campaign: ready-frame/error coalescing starts once and is capped at 300 ms, never extended by later completions. Capture decode/identity/geometry failures are caught before composition, preserving good peers. A role-layer rejection is classified as no-input only while the actual input port has never been entered for that action; any exception after entry remains unknown. Per-workset read retries cap at three, with at most three fresh session attempts per target. The current typed-value/choice work unit is explicit and does not claim generic application semantics. Arbitrary controller-crash fleet resumption is not automatic; local durable intent fails closed and the original server spool must be reconciled before further input.

Before the first 100-desktop model session, review found that exhausted reads were not projected distinctly from actionable targets. That pre-input campaign was stopped with zero provider sessions and independently verified zero server input/business records; its 100 provisioned containers were preserved in records and destroyed. The follow-up exposes `deferred` plus a `workset.can_end` signal, keeps deferred targets eligible for later host attempts, and caps each model session at 96 tools / 1,000,000 tokens in addition to its wall deadline and the shared arm budgets. A combined 100-target regression requires one permanently unreadable target to remain unfinished while the other 99 finish exactly once.

The third formal pair exposed a post-operation collection failure: all 300 inputs and model confirmations finished, and the server persisted its complete reply, but the host transfer timed out. The completed arm is recovered from the original hashed server receipt without replay; its unpersisted arm elapsed time remains null. Host recovery now persists a measurement checkpoint before grading, rereads only the exact finish request's immutable receipt through a compressed transfer if necessary, and supports `managed-run.ts CONFIG --resume` solely for an independently audited completed prefix followed by untouched runs. A partially executed arm still requires explicit evidence reconciliation and is never restarted by this command. Continuations preserve the original plan, compare task/tools/model/config/order and all non-recovery source hashes, and append a separate full source manifest. These host recovery changes do not establish uninterrupted lifecycle reliability for the failed run and must be disclosed in the report.

After all formal operations ended, a truncated JSON reply at EOF was reproduced in a real relay process: readline's final fragment event incorrectly failed all pending requests. The transport now accepts only newline-terminated replies, bounds the unfinished line by bytes, and reconnects to the same immutable IDs without extending original deadlines. A malformed complete line still fails closed. The process test proves the executed effect is not repeated. No captured wire fragment proves this was the sole cause of the live fault, and this post-measurement fix is not included in the formal performance results. Missing elapsed stays null in analysis; unavailable timing and incomplete runtime closure are exposed separately from full business submission.
